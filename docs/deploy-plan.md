# 公開の計画（D案：今のサーバーの入口に、静的サイトを置く）

## 方針
- ドメイン（DNS）は変えない。`/kdhs/`（別のWordPress、約5.5GB）は、そのまま。
- GitHubを元データの保管場所にする。サーバーへの転送は、GitHub Actions（`.github/workflows/deploy.yml`）を、手動で実行する。
- 転送は「追加と上書き」だけで、削除はしない。サーバー側のファイルは、勝手には消えない。

## 段階
| 段階 | 内容 | 担当 |
|---|---|---|
| 0 | サーバーが、FTPS か SFTP に対応しているか確認する（FTPは、通信が暗号化されないため、避ける） | あなた（サーバー会社に確認） |
| 1 | **サーバー全体のバックアップ**を、サーバー会社の機能で取る（`/kdhs/` を含む） | あなた |
| 2 | GitHubに、転送用の認証情報を登録する（Settings > Secrets and variables > Actions）。**チャットには書かない** | あなた |
| 3 | 試験用フォルダ `staging_new` へ転送する（まず、試し実行） | Claude（手順の案内）とあなた（実行） |
| 4 | `https://kurume-dental.or.jp/staging_new/` で、表示を確認する（画像、リンク、スマホ表示、ブラウザのエラー） | あなた、Claude |
| 5 | 公開直前の確認：安全のための設定（`deploy/htaccess-root.txt`）を、試験用フォルダで試す | Claude |
| 6 | 入口（`.`）へ転送する。WordPress本体の `index.php` などは、削除せず、名前を変えて残す（元に戻せるように） | あなた（実行）、Claude（手順の案内） |
| 7 | 公開後の確認。問題があれば、元に戻す（名前を変えたファイルを戻す） | あなた、Claude |
| 8 | 数週間の様子を見て、古いWordPress本体の不要なファイルを、削除する | あなた |

## 注意
- 入口の WordPress と `/kdhs/` の WordPress は、別のものとして、扱う。`/kdhs/` の中身は、触らない。
- 入口への転送は、`confirm_root` に `DEPLOY-TO-ROOT` と入れないと、動かない。
- `Settings > Environments > production` に、承認者を設定すると、承認なしには転送できない。
- 会員ページは、新サイトにない。旧URLにアクセスされた場合は、404になる。会員への案内が、別途、必要。
